# 結果速報：券の読込と公開状態

2026-11-08の本線4点に支持順位・理由を追加した際、`.ticket.textContent`を券として扱う旧処理が注釈まで取り込み、全件を不正券と判定した。

## 読込契約

- 集計キーは合法なユニーク3連単の`1-2-3`形式。表示順位・説明をキーに混ぜない。
- `data-ticket`があれば厳密検証する。艇番カラーの直接子`.bnum`と併存する場合は一致を検証する。
- `.bnum`だけの既存紙面も対応し、順位理由に含む数字は読まない。旧プレーン券は注釈要素を除いた全体が合法券の時のみ採用する。
- 表示を検索してもっともらしい3桁を拾わない。不正券・数字の不一致は未確認のまま。AIの券・順序・理由・凍結原本を修正しない。
- `main`の3点/4点は原本の実点数で採点する。区分内の重複を除き、区分間の重複は従来通り別購入として扱う。

## Gemi兄の公開状態

既存発行処理が古い`gemi_publication_pending`を保持する場合がある。同日JSTの観測済み初回公開時刻があり、公開データが`published`かつ各Rの締切前であれば、その公開証跡を優先する。

時刻欠落・不正・未来・別日、締切後公開、`retrospective`、`POST_DEADLINE`、凍結が締切後と明示された原本は除外を継続する。これは公開速報の表示接続の修正であり、正式BCの認定・分母・保存原本の変更ではない。

予想原本が登録済みなのに読込できなければ「予想データを読み込めませんでした」と表示し、正常な未発行・未集計と混同させない。
